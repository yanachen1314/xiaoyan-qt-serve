# 工具使用校验实施计划

## 目标

在 `xiaoyanQt_serve` 中实现统一工具校验网关，并改造 `xygoMain` 豆包工具，使每次解析都必须完成公众号验证码校验。工具解析请求由新的 Spring Boot 接口接收，再转发到当前 Flask 豆包 API，并将结果返回前端。

设计文档：`docs/plans/2026-06-04-tool-auth-design.md`

## 执行原则

- 先写测试，再写实现。
- 每个工具令牌只能消费一次。
- `X-Device-Id` 使用浏览器指纹摘要。
- 工具 JWT 与管理员 JWT 区分用途，不共用管理员登录令牌语义。
- 不迁移 Flask 豆包解析器，只做 Spring Boot 网关转发。

## 任务 2：实现工具 JWT 服务

文件：

- `src/main/java/com/yan/xiaoyanqtserve/service/impl/tool/ToolJwtService.java`
- `src/test/java/com/yan/xiaoyanqtserve/tool/ToolJwtServiceTest.java`

测试：

- 可以生成包含 `typ=tool-token`、`toolCode`、`deviceIdHash`、`openIdHash`、`jti` 的 JWT。
- 可以解析有效工具 JWT。
- 管理员 JWT 或缺少工具声明的 JWT 不通过工具校验。
- 过期 JWT 不通过校验。

实现：

- 复用 `jjwt` 和 `KeysUtil`。
- 使用独立的工具令牌 subject 和 audience。
- 不改变现有管理员 `JwtUtil` 行为。

验证：

```bash
mvn -Dtest=ToolJwtServiceTest test
```

## 任务 3：实现验证码和一次性令牌状态服务

文件：

- `src/main/java/com/yan/xiaoyanqtserve/service/impl/tool/ToolAuthService.java`
- `src/main/java/com/yan/xiaoyanqtserve/common/dto/tool/ToolVerifyRequest.java`
- `src/main/java/com/yan/xiaoyanqtserve/common/dto/tool/ToolVerifyResponse.java`
- `src/test/java/com/yan/xiaoyanqtserve/tool/ToolAuthServiceTest.java`

测试：

- 保存验证码后可以用正确验证码换取 JWT。
- 换取成功后验证码被删除。
- 错误验证码会增加失败次数。
- 超过失败阈值后拒绝验证。
- 同一个 `jti` 第一次消费成功，第二次消费失败。
- 设备指纹不一致时拒绝消费。
- 工具编码不一致时拒绝消费。

实现：

- Redis key 使用设计文档中的命名。
- `jti` 消费需要原子化。可以在 `RedisUtil` 增加 `getAndDelete`，或使用 Redis 锁保护消费逻辑。
- 日志只记录哈希或脱敏信息。

验证：

```bash
mvn -Dtest=ToolAuthServiceTest test
```

## 任务 6：新增 Spring Boot 豆包工具代理接口

文件：

- `src/main/java/com/yan/xiaoyanqtserve/controller/publicApi/DoubaoToolController.java`
- `src/main/java/com/yan/xiaoyanqtserve/service/impl/tool/DoubaoToolProxyService.java`
- `src/test/java/com/yan/xiaoyanqtserve/tool/DoubaoToolControllerTest.java`

测试：

- 缺少 `X-Tool-Token` 时拒绝。
- 无效 JWT 时拒绝。
- 有效 JWT 会被消费，并转发到 Flask 图片接口。
- 有效 JWT 会被消费，并转发到 Flask 视频接口。
- 同一 JWT 重复请求时第二次失败。
- Flask 返回 400 时，Spring Boot 返回可展示的错误信息。

实现：

- 路径：
  - `POST /api/public/tools/doubao/images/analyze`
  - `POST /api/public/tools/doubao/videos/analyze`
- 使用 Spring HTTP 客户端请求配置中的 Flask 地址。
- 转发请求体中的 `url`。

验证：

```bash
mvn -Dtest=DoubaoToolControllerTest test
```

## 任务 7：前端新增浏览器指纹和工具校验 API

文件：

- `xygoMain/src/utils/browserFingerprint.js`
- `xygoMain/src/api/toolAuthApi.js`
- `xygoMain/src/js/request.js`
- `xygoMain/src/__tests__/tool-auth-api.spec.js`

测试：

- `request.js` 请求会自动带 `X-Device=WEB`。
- `X-Device-Id` 来自浏览器指纹摘要。
- 不支持指纹能力时回退到本地 UUID。
- `verifyToolCode` 请求 `/public/tool-auth/verify`。

实现：

- 采集浏览器环境信息后 SHA-256。
- 只发送摘要，不发送原始指纹字段。
- 指纹结果缓存到 `localStorage`，减少重复计算。

验证：

```bash
npm test -- src/__tests__/tool-auth-api.spec.js
```

## 任务 8：前端改造豆包工具调用链路

文件：

- `xygoMain/src/views/tools/DoubaoView.vue`
- `xygoMain/src/api/doubaoApi.js`
- `xygoMain/src/__tests__/doubao-view.spec.js`
- `xygoMain/src/__tests__/doubao-api.spec.js`

测试：

- 点击解析只打开验证码弹窗，不直接调用解析。
- 验证码提交后先调用 `verifyToolCode`。
- 成功后使用 `toolToken` 调用新的 Spring Boot 豆包接口。
- 图片模式调用 `/public/tools/doubao/images/analyze`。
- 视频模式调用 `/public/tools/doubao/videos/analyze`。
- 源码中不再存在固定 `1234` 校验。

实现：

- 移除前端固定验证码判断。
- `analyzeDoubaoImages(url, toolToken)` 和 `analyzeDoubaoVideos(url, toolToken)` 增加 token 请求头。
- 验证失败时保留弹窗并展示错误。

验证：

```bash
npm test -- src/__tests__/doubao-view.spec.js src/__tests__/doubao-api.spec.js
```
